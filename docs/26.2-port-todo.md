## 2. 为什么要停用：26.2 的渲染层是重构而非改名

26.2 移除了本项目自绘管线所依赖的核心类型。已通过官方
**NeoForge 26.1 -> 26.2 Mod Migration Primer** 与 26.2 jar 反射确认：

- MultiBufferSource **接口被移除**，由 feature / SubmitNode 系统取代
- OutlineBufferSource **被移除**
- RenderBuffers#bufferSource / outlineBufferSource -> stagedVertexBuffer
- RenderPipeline.Builder 的 withSampler / withUniform -> withBindGroupLayout
- withVertexFormat(format, mode) -> withVertexBinding(index, format) + withPrimitiveTopology(...)
- withDepthWrite / withDepthTestFunction -> withDepthStencilState(DepthStencilState)；DepthTestFunction 已不存在
- TextureTarget / RenderTarget 现在需要 GpuFormat
- GlDevice 不再是 public（DirectStateAccess 的方法反而变为 public）

> 注意：**这与 Vulkan 无关**。即使只用 OpenGL，上述类型也已被替换。
> 官方 primer 全文见 research/primer-26.2.md（另有 26.1 / 26.3 / 1.21.11 版本可对照）。

### P0 - 恢复自定义 RenderPipeline
文件：pending-port/.../HeldItemOutlinePipelines.java

需把 8 条管线改写为新的 builder 形态：

    // 旧（1.21.11）
    RenderPipeline.builder()
        .withSampler("MaskSampler")
        .withUniform("OutlineInfo", UniformType.UNIFORM_BUFFER)
        .withVertexFormat(DefaultVertexFormat.EMPTY, VertexFormat.Mode.TRIANGLES)
        .withDepthWrite(false)
        .withDepthTestFunction(DepthTestFunction.NO_DEPTH_TEST)
        .withBlend(BlendFunction.TRANSLUCENT)

        .withBindGroupLayout(BindGroupLayout.builder()...build())
        .withVertexBinding(0, DefaultVertexFormat.EMPTY)
        .withPrimitiveTopology(PrimitiveTopology.TRIANGLES)
        .withDepthStencilState(new DepthStencilState(CompareOp.ALWAYS_PASS, false))

参考：RenderPipelines 中已有的 POST_PROCESSING_SNIPPET，以及
BindGroupLayout.builder() / BindGroupLayout$UniformDescription。

### P1 - 重写渲染主体
文件：pending-port/.../HeldItemOutlineRenderer.java（原 153 个错误）

这是最大的一块。原实现依赖已移除的 MultiBufferSource，需要改为：

- 用 SubmitNodeStorage 收集提交，再用
  Minecraft.getInstance().gameRenderer.featureRenderDispatcher().renderAllFeatures(storage)
  或 prepareFrame(storage) + executeSolid/executeTranslucent/... 驱动
- 需要自定义 feature 时：实现 SubmitNode（可派生 TranslucentSubmit / BatchableSubmit）、
  FeatureRenderPhase（或直接用 SimpleFeatureRenderPhase / TranslucentFeatureRenderPhase）、
  以及 FeatureRenderer（含 RenderType 的可继承 RenderTypeFeatureRenderer）
- 取投影矩阵改用 ProjectionMatrixBuffer + Projection
  （PerspectiveProjectionMatrixBuffer / Cached* 已移除）
- 颜色一律用 Vector4fc；RenderPass#draw 签名已变（原 OptionalInt 不兼容）
- 需要 GL 直连处：GlDevice 已非 public，但 DirectStateAccess 方法已转 public，
  可评估是否不再需要 GlDeviceAccessor
- TextureTarget 构造需传 GpuFormat

### P2 - GUI 描边管理
文件：pending-port/.../GuiItemOutlineManager.java（原 25 错）
依赖 P0/P1，并需对齐 GuiRenderer 的新构造（不再接收 SubmitNodeCollector / BufferSource）。

### P3 - 配置界面物品预览

PictureInPictureRenderer 的变化：
- 构造不再接收 MultiBufferSource$BufferSource

### P4 - 世界渲染入口

HeldItemOutlineRenderer.beginMainWorldPass()。该 Fabric API 事件在 26.2 已移除，

当前该调用已被注释，位置见 ItemGlintRelightClient#onInitializeClient 的 TODO。

### P5 - 恢复 mixin
把 pending-port 中的 8 个 mixin 移回 src/client/java，并逐一对齐 26.2 目标：

- OrderedSubmitNodeCollector#submitModelPart 去掉了两个 boolean 参数

- FeatureRenderDispatcher 不再接收 SubmitNodeStorage / BufferSource / OutlineBufferSource
- RenderPipelines 深度语义反转：CompareOp 由 LESS_THAN_OR_EQUAL 变为 GREATER_THAN_OR_EQUAL

## 6. 注意事项

- **不要修改 common/src/client/java**：它仍被 1.21.11 使用，26.2 已 fork 出自己的副本。
  两边 API 已不可调和（GuiGraphics 被删），修改会直接破坏 1.21.11。
- common/src/main/java（配置模型）仍是共享的，26.2 与其兼容（0 错误），可继续共用。
- pending-port 保留了原始相对路径，恢复时按路径移回即可。
- 26.2 是**无混淆**版本，走 no-remap Loom：没有 modImplementation 等 remap 配置，
  依赖用常规 implementation / compileOnly / localRuntime。
