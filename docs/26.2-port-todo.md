## 2. 重要教训：编译通过 != mixin 能在运行时应用

挂起渲染文件后，构建一度是绿的，但 `runClient` **仍然崩溃**：

    Mixin apply for mod itemglintrelight failed
      itemglintrelight.client.mixins.json:GlTextureViewAccessor
      -> com.mojang.blaze3d.opengl.GlTextureView
    InvalidAccessorException: No candidates were found matching
      getFbo(Lcom/mojang/blaze3d/opengl/DirectStateAccess;Lcom/mojang/blaze3d/textures/GpuTexture;)I

原因：`@Invoker("getFbo")` / `@Accessor("...")` 的目标是用**字符串**写的，
编译器无法校验；目标方法在 26.2 消失也不会报编译错，只在运行时炸。

**因此：每次改动 mixin 配置后，必须实际跑一次 `runClient` 看日志，不能只看 build 是否绿。**
本次就是靠实测发现并修掉这个崩溃的。

## 3. 26.2 渲染层是重构而非改名

26.2 移除了本项目自绘管线依赖的核心类型（经官方 NeoForge 26.1 -> 26.2 Primer 与 jar 反射确认）：

- `MultiBufferSource` **接口被移除**，由 feature / SubmitNode 系统取代
- `OutlineBufferSource` **被移除**
- `RenderBuffers#bufferSource / outlineBufferSource` -> `stagedVertexBuffer`
- `RenderPipeline.Builder`：`withSampler / withUniform` -> `withBindGroupLayout`
- `withVertexFormat(format, mode)` -> `withVertexBinding(index, format)` + `withPrimitiveTopology(...)`
- `withDepthWrite / withDepthTestFunction` -> `withDepthStencilState(DepthStencilState)`；`DepthTestFunction` 已不存在
- `TextureTarget` / `RenderTarget` 现在需要 `GpuFormat`
- `GlDevice` 不再是 public（`DirectStateAccess` 的方法反而变为 public）

> **这与 Vulkan 无关**：即使只用 OpenGL，上述类型也已被替换。
> 官方 primer 全文见 `research/primer-26.2.md`（另有 26.1 / 26.3 / 1.21.11 版本对照）。

### P1 - 重写渲染主体（最大一块）
`pending-port/.../HeldItemOutlineRenderer.java`（原 153 错）

- 用 `SubmitNodeStorage` 收集提交，再由
  `Minecraft.getInstance().gameRenderer.featureRenderDispatcher().renderAllFeatures(storage)`
  或 `prepareFrame(storage)` + `executeSolid/executeTranslucent/...` 驱动
- 自定义 feature：实现 `SubmitNode`（可派生 `TranslucentSubmit` / `BatchableSubmit`）、
  `FeatureRenderPhase`（或用 `SimpleFeatureRenderPhase` / `TranslucentFeatureRenderPhase`）、
  `FeatureRenderer`（含 `RenderType` 可继承 `RenderTypeFeatureRenderer`）
- 投影矩阵改用 `ProjectionMatrixBuffer` + `Projection`
  （`PerspectiveProjectionMatrixBuffer` / `Cached*` 已移除）
- 颜色统一 `Vector4fc`；`RenderPass#draw` 签名已变（原 `OptionalInt` 不兼容）
- GL 直连：`GlDevice` 已非 public，但 `DirectStateAccess` 方法已转 public，可评估去掉 `GlDeviceAccessor`
- `TextureTarget` 构造需传 `GpuFormat`

### P2 - GUI 描边管理
`pending-port/.../GuiItemOutlineManager.java`（原 25 错）
依赖 P0/P1，并对齐 `GuiRenderer` 新构造（不再接收 `SubmitNodeCollector` / `BufferSource`）。

### P3 - 配置界面物品预览
`pending-port/.../ItemPreviewRenderer.java`（原 20 错）
`PictureInPictureRenderer`：构造不再接收 `MultiBufferSource$BufferSource`；
`prepare` 改收 `FeatureRenderDispatcher`；`renderToTexture` 改收 `SubmitNodeCollector`。

### P4 - 世界渲染入口
原 `ItemGlintRelightClient` 用 `WorldRenderEvents.START_MAIN` 触发
`HeldItemOutlineRenderer.beginMainWorldPass()`。该事件在 26.2 已移除，需找替代入口
（新的渲染事件，或注入 `GameRenderer` / `Hud`）。当前调用已注释，见
`ItemGlintRelightClient#onInitializeClient` 的 TODO。

### P5 - 恢复 mixin（15 个）
移回 `src/client/java`，逐一对齐 26.2：

- `OrderedSubmitNodeCollector#submitModelPart` 去掉两个 boolean 参数
- `submitMovingBlock` 现接收 `int` outline color
- `FeatureRenderDispatcher` 不再接收 `SubmitNodeStorage` / `BufferSource` / `OutlineBufferSource`
- `RenderPipelines` 深度语义反转：`CompareOp` 由 `LESS_THAN_OR_EQUAL` 变 `GREATER_THAN_OR_EQUAL`
- **7 个 accessor 的目标多为 26.2 内部实现细节**，需逐个核对新签名
  （`GlTextureViewAccessor#getFbo` 已确认失效，其余待验）

**改完必须实际跑 `runClient` 验证 mixin 应用成功**（见 §2）。

## 7. 注意事项

- **不要修改 `common/src/client/java`**：它仍被 1.21.11 使用，26.2 已 fork 自己的副本。
  两边 API 已不可调和（`GuiGraphics` 被删），改动会直接破坏 1.21.11。
- `common/src/main/java`（配置模型）仍共享且与 26.2 兼容（0 错误），可继续共用。
- `pending-port` 保留了原始相对路径，恢复时按路径移回即可。
- 26.2 是**无混淆**版本，走 no-remap Loom：没有 `modImplementation` 等 remap 配置，
  依赖用常规 `implementation` / `compileOnly` / `localRuntime`。
